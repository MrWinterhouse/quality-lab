01 · The system

A product worth testing, not a to-do list worth automating

Most QA portfolios automate a demo shop. This one starts with the thing that makes quality engineering hard: rules that decide whether someone gets healthcare, a vendor that fails after doing the work, two agencies that must never see each other’s applicants, and a model whose output nobody can fully predict.

The product is a benefits-eligibility service for two tenant agencies. Applicants screen a household against Medicaid, SNAP, WIC and CHIP, submit an application, upload documents, and wait for an asynchronously verified income check. A caseworker reviews and decides. An in-house assistant answers policy questions.

It runs offline on Node’s standard library with an in-memory store, so every claim on this site reproduces from a clean checkout with npm install and one command. No accounts, no API keys, no cloud spend.

03 · Four defects

Triage, root cause, fix, regression

Each case study follows the same arc: the risk, the smallest reproduction, the line of code that caused it, the test that now fails if it returns, and what the evidence still does not cover. All four are seeded defects in the product — the probes that catch them ship red on purpose.

Case 01 · Authorization

Every agency sees the first agency’s configuration

A module-level cache keys tenant config by nothing at all, and the screening endpoint skips the ownership check that every other read enforces. Agency B reads agency A’s applicants — and its programs, branding and 30-day deadline are replaced by agency A’s 10-day one.

DEFECT-04 · DEFECT-05Read → Case 02 · Async integration

One application, two income verifications

The retry loop builds its idempotency key from the attempt number. A vendor that processes the request and then times out produces a second, undeduplicated record on retry — while the timeline shows a single, clean success.

DEFECT-07Read → Case 03 · AI behavior

The guardrail ran, found three violations, and shipped them

The vulnerable prompt discloses its own instructions, guarantees Medicaid eligibility and invents $973 a month. The guardrail evaluator flagged all three — the response path only enforces it on the newer prompt version, which agency A does not use.

DEFECT-11Read → Case 04 · Rules and differential testing

A family of four is told it qualifies. It doesn’t.

Biweekly pay is annualized over 24 periods instead of 26, and the Alaska/Hawaii poverty multipliers are declared and then ignored. Two silent wrong answers in opposite directions, found by comparing the API to an independently written oracle.

05 · Approach

Four things I keep doing

None of these are tool choices. They are the decisions that made the difference between a suite that reports green and a suite someone trusts before a release.

Risk before coverage
The first question is who gets hurt and how quietly, not which framework to use. Tenancy and PII outrank a prettier page object.
Independent oracles
Rules are checked against a second implementation written from the specification, not copied from production. Copied logic agrees with itself and proves nothing.
Gates that can say no
A report that always reads READY is decoration. This one returns NOT READY and names the five things that would change it.
Evidence over adjectives
Every claim on this site links to a command, a file and a failing assertion. “Tested thoroughly” is not a finding.
