How this chatbot is tested

A chatbot that answers questions about its own quality work should be the easiest thing on the site to audit. It is the same pattern as the product assistant: a golden dataset, programmatic assertions, and a gate that fails the build rather than describing the failure afterwards.

Latest run: 52 golden cases, 52 passed, 0 failed. Read the per-case report →

Each answer in the conversation above carries a “How this answer is tested” panel: the cases in the dataset that assert that answer's topic, and the assertion each case makes. The panel reads site/chat/coverage.json, which npm run test:chatbot generates from the dataset — a committed copy that no longer matches the dataset fails that run.

What the dataset asserts

  • Routing. The reply must come from the expected knowledge-base entry, so a keyword change cannot silently turn a hiring answer into a security answer.
  • Required facts. Concrete figures such as the 26 pay periods, the 15 probes and the five open risks have to appear, not be approximated.
  • Forbidden content. No invented salary, no unstated availability date or work-authorization claim, no echoed SSN, no leaked setup text.
  • Citations. Every substantive answer carries at least one source; refusals cite the contact instead of nothing.
  • Refusal flag and length. The machine-readable field must agree with the prose, and a rambling answer fails its word budget.

npm run test:chatbot runs the golden dataset against site/chat/engine.js — the exact file the browser loads — and exits non-zero on a single failed case, naming the case and the assertion.

What it does not prove

Matching is keyword-based, not semantic: keyword words may appear in any order, and a question nothing matches still refuses, naming the closest published topics. A paraphrase the dataset does not contain can still route to the wrong entry. The dataset was written by the same person who wrote the answers, so it checks consistency and grounding, not whether these are the best answers to give.

A 100% pass rate is evidence about the cases in the file. It is not a claim that the assistant cannot mislead — which is why it refuses instead of guessing when the knowledge base has nothing.
